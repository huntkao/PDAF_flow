Repeat Pattern 下的信心盲點 — 合成資料推演

延續 m2-estimator-hw-cost-characteristics（真實硬體 cost 序列分析），但這裡不是量測，是推演： 真實硬體那批資料剛好沒有出現「多個競爭谷同時逼近主谷」的情境，所以看不出問題。 這裡改用自製合成 cost 曲線，把「有幾個競爭谷」這個變數單獨拉出來測試， 確認現有 unamb 指標對 repeat pattern 場景（週期性重複紋理造成多個近乎打平的候選谷）有沒有真正的盲點。

背景：為什麼現有 unamb 可能不夠

ParabolicDepthEstimator::estimateTraced()（src/algo/parabolic_depth_estimator.cpp）目前用單一次低點衡量歧義： 

// basin 外唯一一個全域次低點，跟主谷深度比
t.unamb = (t.second - t.cmin) / depth_abs;

這是 stereo/PDAF confidence 常見的 PKRN（peak-to-second-peak ratio）家族做法，對「單一孤立假谷」（雜訊、局部遮蔽）有效。 但 repeat pattern 的訊號特徵不是「一個次低點」，而是多個等距、深度相近的谷——這正是本專案 CLAUDE.md 已記錄的 aliasing 根因（紋理頻率超過 π/max_shift）。unamb 只取全域最低的那一個競爭者， 不管背後還有幾個一樣深的谷排在後面。

實驗設計

用合成資料把「深度比」跟「競爭谷數量」兩個變數解耦，分別測試。

  1. 固定深度比 r——主谷與最接近的競爭谷的 cost 比值（1.05 / 1.15 / 1.30 / 1.60，r 越接近 1 越危險）。
  2. 只改變競爭谷數量——1 個 / 2 個 / 4 個，全部設在同一個深度比 r 上，週期 13（間距遠大於谷寬 σ=2.5， 避免跟主谷高斯重疊，也避開邊界 index 0/64，確保每個谷都是乾淨獨立的局部極小值）。
  3. 無雜訊時跑 estimateTraced()——驗證假設：因為 unamb 只取全域最低競爭者， 同一個 r 底下不管幾個競爭谷，unamb 應該幾乎不變。
  4. 疊加高斯雜訊做 Monte Carlo（雜訊標準差 = 主谷深度的 10%，2000 次試驗／情境）， 統計 argmin 落在「非主谷」的機率——這是模擬 frame-to-frame 量測雜訊下真正的 AF hunting 風險， 也是 confidence 這個數字理論上該預測的東西。
  5. 跟真正的 C++ 生產路徑交叉驗證——python 移植版的 unamb 數字對照 run_estimate（直接連結 src/algo/parabolic_depth_estimator.cpp）的輸出，逐條核對到小數點後三位。

發現：unamb 量不到「數量」，只量得到「最深的那一個」

盲點確認

r=1.05 時，unamb 從 1 個競爭谷的 0.059 只爬到 4 個競爭谷的 0.089（+50%）， 但實測 hunting 機率從 0.330 飆到 0.635（+92%，接近翻倍）。unamb 的變化幅度遠遠跟不上真實風險的變化幅度。

上一輪曾經提過「多競爭者深度聚合」（例如對多個近乎打平的谷深度取調和平均）作為候選方案， 但這裡的合成設計刻意讓所有競爭谷深度比相同，調和平均自然趨近單一值——深度聚合抓不到「數量」這個維度， 因為 hunting 風險的物理機制不是深度平均，而是「多次獨立雜訊試驗，只要有一次雜訊讓某個競爭谷贏過主谷就算輸」， 這是組合機率問題，不是深度問題。

結論與後續

建議

不建議再往「深度聚合」方向修 unamb——本實驗已證明那條路線在數量效應上是無效的。 應該直接把「有幾個近乎打平的競爭谷」當成獨立訊號輸出，例如在 DepthEstimateTrace／DepthEstimate 新增一個 count_near（basin 外、深度落在容忍帶內的局部極小值個數）， 交給下游（AfController 或未來的仲裁層）套用組合機率式的策略（例如 count_near ≥ 2 時 強制走保守分支、降低 max_retries、或改變重試策略），而不是硬塞進單一 confidence scalar ——這維持 M2（純量測）與仲裁邏輯分離的架構分工。

更新：count_near 已實作——落在 DepthEstimateTrace（src/algo/parabolic_depth_estimator.{h,cpp}）， 定義為 basin 外、深度落在 second 10% 容忍帶內的局部極小值個數，純診斷欄位， estimate()/confidence 公式與 DepthEstimate 公開介面都尚未改動。 單元測試（tests/test_depth_estimator.cpp，DepthEstimatorTrace.CountNear*）用一組 mean 配平的範例直接證明「unamb 完全相同、count_near 不同」的盲點確實存在於生產路徑上。 是否接入 confidence 公式或 AfController 仲裁策略，留待後續評估。
